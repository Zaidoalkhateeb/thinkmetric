# ThinkMetric Website

Production website for ThinkMetric's wind and atmospheric LiDAR equipment,
meteorological measurement systems, and autonomous remote-power solutions.

The site uses React 19, Vite, React Router, and a custom CSS design system.
Company and catalogue content are kept separate from presentation components.

## Requirements

- Node.js 22 (see `.nvmrc`)
- npm

## Local development

```bash
npm ci
npm run dev
```

Quality and production commands:

```bash
npm run lint       # static analysis
npm run test:run   # unit, component, metadata, and route tests
npm run sitemap    # regenerate sitemap.xml from source data
npm run build      # validated production build into dist/
npm run check      # lint + tests + sitemap validation + build
npm run preview    # serve the production build locally
```

## Project structure

```text
src/
  components/      Reusable interface components
  data/            Company, category, country, and product content
  pages/           Route-level page components
  styles/          Global design tokens and shared styles
  test/            Shared Vitest browser setup
  utils/           Testable business rules and helpers
scripts/           Build-time content generators
public/            Static images, video, SEO, and hosting files
```

Pages are loaded with `React.lazy`, so each route receives its own JavaScript
and CSS chunks. Leaflet and its stylesheet are imported only when the location
map approaches the viewport.

## Editing content

Company details, contact information, categories, About copy, and process
content live in `src/data/siteContent.js`. The complete catalogue lives in
`src/data/products.js`.

Each product is normalized to this public shape:

```js
{
  slug: 'windhorizon-h400',
  modelName: 'WindHorizon H400',
  productType: 'Nacelle Wind LiDAR',
  categorySlug: 'lidars',
  categoryLabel: 'Lidars',
  summary: '...',
  features: [],
  applications: [],
  optionalExtras: [],
  specifications: [],
  image: '/images/products/windhorizon-h400.webp',
  pdfUrl: null,
  contentStatus: 'documented',
}
```

Do not invent specifications, certifications, testimonials, or locations.
Use `null` or an honest pending state until approved material is available.

After adding, removing, or renaming a category or product, run:

```bash
npm run sitemap
npm run check
```

Catalogue integrity tests detect duplicate slugs and invalid category links.

## Product media and documents

Store approved product images in `public/images/products/`, preferably as
WebP. Set the matching product's `image` value to its root-relative path.

Store approved datasheets in `public/documents/products/` and set `pdfUrl` on
the corresponding product when document actions are enabled.

Homepage video and poster files live in `public/media/`. Keep the WebM, MP4,
and poster versions synchronized. Reduced-motion users receive the poster
instead of autoplay video.

## Contact form

Production submissions are sent to `/api/contact.php`, which validates the
request and sends it to `sales@think-metric.co` through PHP `mail()`. The
recipient is fixed in server-side code and cannot be changed by visitors. The
handler includes a honeypot, request-size limits, same-origin checks, header
injection protection, and per-IP rate limiting.

Set the following only when replacing the included PHP handler:

```dotenv
VITE_CONTACT_FORM_ENDPOINT=https://your-endpoint.example.com/contact
```

During local Vite development, where PHP is not running, a successful validated
submission opens a pre-filled email draft to the same sales mailbox. Validation
and fallback email rules live in `src/utils/contactForm.js` and are covered by
automated tests.

## Map

The location map uses Leaflet with CARTO Voyager tiles. The approved address,
coordinates, and Google Maps links are defined once in
`src/data/siteContent.js`.

## Routes

```text
/                                      Home
/products                              Product catalogue
/products/:categorySlug                Category catalogue
/products/detail/:productSlug          Product detail
/about                                 About
/contact                               Contact
*                                      Branded 404 page
```

## Deployment and launch checks

`npm run build` first verifies that `public/sitemap.xml` matches the current
routes and catalogue. The sitemap is generated by
`scripts/generate-sitemap.mjs` and currently includes all fixed, category,
and product routes.

`public/_redirects` provides the SPA history fallback on Netlify-compatible
static hosting. Configure an equivalent rewrite to `/index.html` on other
hosts.

For myVesta, upload the contents of `dist/` to the domain's `public_html`
directory and use a PHP-FPM-enabled web template. The build includes
`.htaccess` for React Router fallback and `api/contact.php` for email delivery.
Create or authorize `no-reply@think-metric.co` as a sender and test delivery to
`sales@think-metric.co` after deployment.

GitHub Actions runs `npm ci` and `npm run check` for pushes to `main` and for
pull requests. Dependabot monitors npm packages and GitHub Actions versions.

Before launch, also verify the deployed site with real mobile devices,
keyboard navigation, link-preview tools, and a Lighthouse run against the
production domain.

## Remaining content work

- Add approved datasheets and expose the associated product actions.
- Keep product photography and technical specifications synchronized with
  manufacturer-approved material.
- Configure and test the production form endpoint if email drafts are not the
  desired long-term submission flow.
